# 画像前処理 検証デモ（実験記録）

> **⚠️ 重要**：このデモは **検証目的で作成した実験アプリ**です。  
> 実機テストの結果、このデモで試みた OpenCV ベースの前処理（二値化・CLAHE・ノイズ除去など）は **PaddleOCR の認識精度を低下させる**ことが判明しました。  
> そのため、**本番アプリには採用されていません**。本番アプリの前処理はリサイズのみです。

---

## このデモの位置づけ

鉄骨文字認識の開発初期、「OpenCV による前処理を加えれば PaddleOCR の精度が上がるのでは」という仮説のもとに作成した比較検証デモです。

```
【検証した仮説】
  撮影
    │
    ▼
┌─────────────────────────────────┐
│  OpenCV 前処理（このデモの範囲）   │
│  グレースケール / CLAHE /         │
│  二値化 / 歪み補正 など           │
└─────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────┐
│  PaddleOCR（DBNet + SVTR）       │
└─────────────────────────────────┘
    │
    ▼
  認識結果
```

**検証結果：仮説は否定された。**  
PaddleOCR は内部で独自の正規化処理を行うため、外部から前処理を加えると情報が失われ、精度が下がることが確認されました。

### 本番アプリの前処理（採用された方針）

```
撮影・ギャラリー読み込み
    │
    ▼
EXIF 回転補正（RecognizeActivity）
    │
    ▼
リサイズのみ 長辺 1280px（ImagePreprocessor.kt）
    │
    ▼
PaddleOCR に渡す（カラー画像そのまま）
```

---

## 実験した前処理パイプライン（本番未採用）

このデモでは 4 つのモードを切り替えて精度・処理時間を比較しました。共通の基本パイプラインは以下のとおりです（STANDARD モード）。

```
元画像（カラー）
    │
    ▼
① リサイズ             最長辺を 960px に縮小（アスペクト比維持）
    │
    ▼
② グレースケール化      BGR → Gray（1チャンネル化）
    │
    ▼
③ CLAHE               局所的なコントラスト補正（照明ムラ・影の対策）
    │
    ▼
④ ガウシアンブラー      ノイズ除去（カーネルサイズ 5×5）
    │
    ▼
⑤ 適応的二値化          局所平均に基づく閾値処理（文字の白黒化）
    │
    ▼
⑥ 極性正規化 + クリーニング  白黒反転・モルフォロジー処理でノイズ除去
    │
    ▼
前処理済み画像（白黒2値）
```

### 4つのモード

| モード | 特徴 | 追加処理 |
|---|---|---|
| **STANDARD** | 基本パイプライン | — |
| **BACKGROUND_NORM** | 錆・不均一照明対策 | 背景正規化（モルフォロジー除算） + CLAHE clipLimit=3.0 |
| **PERSPECTIVE** | 斜め撮影の歪み補正 | Canny + 透視変換（warpPerspective） |
| **FULL** | 全改善（最高精度を目指した構成） | 歪み補正 + 背景正規化 + バイラテラルフィルタ |

### パラメータ（STANDARD モード基準）

| ステップ | パラメータ | 値 |
|---------|-----------|---|
| リサイズ | 最大サイズ | 960 px |
| CLAHE | clipLimit | 2.0（BACKGROUND_NORM 時は 3.0） |
| CLAHE | tileGridSize | 8×8 |
| ガウシアンブラー | カーネルサイズ | 5×5 |
| 適応的二値化 | blockSize | 11 |
| 適応的二値化 | 定数 C | 2.0 |

## 検証結果

| 項目 | 結果 |
|------|------|
| テスト画像 | 鉄骨サンプル 18 枚（最大 5712 × 4284 px） |
| 処理時間（実測） | **1127 ms** |
| 要件（3秒以内） | ✅ 達成 |
| OpenCV 初期化 | ✅ 成功 |
| **本番採用** | **❌ 未採用**（PaddleOCR 精度が低下するため） |

> **採用しなかった理由**：このデモの前処理（グレースケール化・二値化）を加えた画像を PaddleOCR に渡すと、前処理なしより認識精度が下がることが実機テストで判明しました。PaddleOCR のモデルはカラー画像（3チャンネル）を入力として学習しており、内部で正規化を行うためです。

## デモアプリの使い方

1. アプリを起動すると、テスト用の鉄骨画像 18 枚が自動で読み込まれる
2. 上部の **「前処理モード」** スピナーで処理モードを選択
3. ドロップダウンで画像を選択（◀ / ▶ でも切り替え可能）
4. **「前処理実行」** ボタンをタップ → 元画像と前処理後の画像を並べて表示
5. **「詳細計測」** ボタンで各ステップごとの処理時間を確認可能
6. **「全画像 一括処理」** ですべての画像を連続処理してサマリー表示
7. **「📥 保存」** / **「全画像 一括保存」** で前処理済み画像をギャラリーに保存

## 起動方法

### A. Android エミュレータで起動する

> Android Studio が必要です（[ダウンロード](https://developer.android.com/studio)）

1. **Android Studio を開く**  
   `File → Open` で `image-preprocessing/` フォルダを選択

2. **エミュレータを作成する**  
   `Tools → Device Manager → + Create Virtual Device`  
   - ハードウェア: **Pixel 7**（推奨）  
   - システムイメージ: **API 34（Android 14）**  
   - 「Finish」で作成  

3. **エミュレータを起動する**  
   Device Manager から ▶ ボタンでエミュレータを起動

4. **アプリをビルド＆起動する**  
   画面右上の **▶ Run ボタン** を押す（または `Shift + F10`）  
   → エミュレータにインストールされて自動で起動

5. **コマンドラインからインストールする場合**（Android Studio 不要）

   ```powershell
   cd image-preprocessing
   .\gradlew.bat installDebug
   ```

---

### B. Android 実機（スマートフォン）で起動する

> USB ケーブルでPCと接続する必要があります

#### 1. スマートフォン側の設定

1. **「設定」→「デバイス情報」→「ビルド番号」** を 7 回タップ  
   → 「開発者向けオプションが有効になりました」と表示される

2. **「設定」→「システム」→「開発者向けオプション」** を開く  
   （機種によって場所が異なる場合あり）

3. **「USBデバッグ」** をオン にする

#### 2. PC側の操作

1. USB ケーブルでスマートフォンとPCを接続する

2. スマートフォンに「**このコンピュータを信頼しますか？**」と表示されたら  
   → **「許可」** をタップ

3. デバイスが認識されているか確認する  
   ```powershell
   adb devices
   ```
   `List of devices attached` の下に `xxxxxxxx device` と表示されれば OK

#### 3. アプリのインストールと起動

**Android Studio から起動する場合:**
1. 画面上部のデバイス選択欄で接続したスマートフォンを選択
2. **▶ Run ボタン** を押す → スマートフォンに自動インストール＆起動

**コマンドラインから起動する場合:**
```powershell
cd image-preprocessing
.\gradlew.bat installDebug
adb shell am start -n com.example.imagepreprocessingtest/.MainActivity
```

#### 4. よくあるトラブル

| 症状 | 対処法 |
|------|--------|
| `adb devices` に表示されない | ケーブルを抜き差ししてスマートフォンで「接続方法」を「ファイル転送(MTP)」に変更 |
| `unauthorized` と表示される | スマートフォン画面で「USBデバッグを許可しますか？」を再確認して「許可」 |
| アプリが起動しない | `adb logcat` でログを確認する |
| OpenCV 初期化失敗 | armeabi-v7a / arm64-v8a ABI がサポートされているか確認（ほとんどの機種は問題なし） |

## ファイル構成

```
image-preprocessing/
└── app/src/main/
    └── java/com/example/imagepreprocessingtest/
        ├── ImagePreprocessor.kt   ← 前処理ロジック（Step 1 の実装本体）
        └── MainActivity.kt        ← デモ用 UI
```

> **注意**：テスト用鉄骨画像（`assets/images/`）と OpenCV ライブラリ（`opencv/`）はリポジトリ管理外です。  
> 画像は Google Drive の共有フォルダから、OpenCV は [OpenCV Releases](https://opencv.org/releases/) からそれぞれ取得してください。

`ImagePreprocessor.kt` が Step 1 の実装本体です。最終的な文字認識アプリに組み込む際は、このクラスをそのまま利用します。
