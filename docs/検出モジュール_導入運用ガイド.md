## 0. 開発・実行のための環境構築手順（前提ソフトウェアの導入）

本システムをローカル環境（開発者が手元で使用するパソコンの環境）でビルド（プログラムの設計図から実際に動くアプリを生成する作業）したり、サーバーを起動したりするために必要な前提ソフトウェアのインストール手順です。

### 1) JDK 17（Java言語でプログラムを開発・実行するための基本キット）の導入
Androidアプリをビルドするために必要です。
1. Oracle（オラクル）の公式サイトなどから「JDK 17」のインストーラーをダウンロードし、インストールを行います。
2. インストール完了後、システムの環境変数に `JAVA_HOME` （インストール先フォルダーの場所）を登録し、`PATH`（プログラムをどこからでも実行できるようにする設定）に `JAVA_HOME\bin` を追加します。

### 2) Android Studio（Androidアプリを開発・構築するための専用ソフトウェア）の導入
Androidアプリのビルドや、スマートフォン実機へのアプリ転送・実行に使用します。
1. Android Studioの公式サイトから最新版をダウンロードし、標準（Standard）設定のままインストールを進めます。これにより、必要なSDK（ソフトウェア開発用の追加ツール集）が自動的にダウンロードされます。
2. 実機スマートフォンをPCとUSB接続してアプリを転送する場合は、スマートフォンの設定画面から「開発者向けオプション」を開き、「USBデバッグ（パソコンからスマートフォンを直接操作する機能）」を有効にしておきます。

### 3) Python 3.10以上（プログラムを動かすための実行環境）とライブラリ（便利なプログラムの部品）の導入（仮想環境の構築）
管理サーバーを起動するために必要です。本プロジェクトでは、PC全体のPython環境に影響を与えないよう、プロジェクト専用の「仮想環境（venv：独立したプログラム実行環境）」を使用します。
1. Pythonの公式サイトから Python 3.10 以上のインストーラーをダウンロードし、インストールします。インストール画面で必ず **「Add python.exe to PATH」**（Pythonを実行するためのパスを自動で追加する設定）にチェックを入れてください。
2. コマンドプロンプトまたはPowerShell（文字でパソコンに命令を与える画面）を起動し、プロジェクトのルートフォルダ（`C:\ソリューション開発`）へ移動します。
3. すでにプロジェクト内にある仮想環境フォルダ（`.venv`）を利用するか、ない場合は以下のコマンドで新しく作成します。
   ```powershell
   cd C:\ソリューション開発
   python -m venv .venv
   ```
4. 仮想環境を有効化（アクティベート：作成した専用環境をPCに認識させる作業）します。
   - **PowerShellの場合**:
     ```powershell
     .venv\Scripts\Activate.ps1
     ```
     ※もし「スクリプトの実行が禁止されている」というエラーが発生した場合は、`Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope Process` を実行してから再度有効化を試してください。
   - **コマンドプロンプトの場合**:
     ```cmd
     .venv\Scripts\activate.bat
     ```
     有効化に成功すると、コマンド画面の入力欄の先頭に `(.venv)` と表示されます。
5. 仮想環境が有効な状態で、以下のコマンドを実行して必要なライブラリを一括でインストールします。
   ```powershell
   pip install -r C:\ソリューション開発\server\requirements.txt
   pip install zeroconf
   ```

## 0-2. Androidアプリのビルド手順

Androidアプリ（スマートフォンで動作する側のプログラム）をビルド（プログラムの設計図から実際に動くアプリを生成する作業）する手順です。コマンドライン（PowerShell等）を使用する方法と、Android Studio（GUI：視覚的にボタンなどを操作する画面）を使用する方法の2通りがあります。

### 1) コマンドライン（PowerShellなど）でビルドする場合
1. PowerShellを起動し、プロジェクトルート（`C:\ソリューション開発`）に移動します。
2. 以下のコマンドを実行して、テスト用のアプリファイル（APK：Androidのアプリインストール用パッケージ）をビルドします。
   ```powershell
   cd C:\ソリューション開発
   .\gradlew.bat assembleDebug
   ```
3. ビルドが成功すると、以下のパスに「`app-debug.apk`」という名前のアプリファイルが生成されます。
   - パス: [app-debug.apk](file:///C:/ソリューション開発/app/build/outputs/apk/debug/app-debug.apk)（`C:\ソリューション開発\app\build\outputs\apk\debug\app-debug.apk`）

### 2) Android Studio（専用開発ツール）でビルドする場合
1. Android Studioを起動し、**「Open」**をクリックして、プロジェクトフォルダ（`C:\ソリューション開発`）を選択して開きます。
2. 初回起動時はプロジェクトの同期（Gradle Sync：ライブラリなどの依存関係を解決して読み込む作業）が自動で走ります。画面右下の進捗バーが消えるまで待ちます。
3. 画面上部のメニューバーから **「Build」** ＞ **「Make Project」** をクリックします。
4. アプリファイル（APK）を明示的に出力したい場合は、メニューバーから **「Build」** ＞ **「Build Bundle(s) / APK(s)」** ＞ **「Build APK(s)」** をクリックします。
5. ビルド完了後、画面右下に表示されるポップアップの「locate」（ファイルの場所を表示）リンクをクリックするか、上記の `app\build\outputs\apk\debug\` フォルダを開くことで、生成された `app-debug.apk` を確認できます。

## 0-3. 管理サーバーの起動・実行手順

管理サーバー（Androidアプリからのデータを受け取り、登録履歴の管理やマスターデータの配信を行うPC側のプログラム）を起動する手順です。

1. PowerShellまたはコマンドプロンプトを起動します。
2. プロジェクトルートへ移動し、Pythonの仮想環境（venv：独立したプログラム実行環境）を有効化（アクティベート：作成した専用環境をPCに認識させる作業）します。
   ```powershell
   cd C:\ソリューション開発
   .venv\Scripts\Activate.ps1  # コマンドプロンプトの場合は .venv\Scripts\activate.bat
   ```
3. サーバープログラムのある `server` フォルダへ移動します。
   ```powershell
   cd server
   ```
4. サーバーのメインプログラムを起動します。
   ```powershell
   python main.py
   ```
5. 起動が成功すると、コマンド画面に以下のようなログが表示されます。
   - `Uvicorn running on http://0.0.0.0:5000`（サーバーが稼働中であることを示します）
   - `[mDNS] Service registered: _crossvision._tcp.local. at <PCのIPアドレス>:5000`（スマホが自動でサーバーを探せるように接続情報を放送していることを示します）
   - `[QR Code URL] http://<PCのIPアドレス>:5000/download`（スマホからアプリをダウンロードするための専用URLです）

6. サーバーの動作確認:
   - PCのブラウザで `http://localhost:5000/admin` にアクセスし、管理者用ダッシュボード（データの登録状況などを一覧確認できるWEB画面）が表示されることを確認します。
   - ブラウザで `http://localhost:5000/health` にアクセスし、画面に `{"status":"ok"}` と表示されることを確認します。

## 0-4. システム全体の動作確認手順（一連の連携テストフロー）

構築した環境で、サーバーとスマホアプリが正しく連携して動作するかを確認する手順です。

1. **管理サーバーの起動**:
   - 上記「0-3. 管理サーバーの起動・実行手順」に従い、PC上でサーバーを起動します。
2. **アプリ（APKファイル）の配置**:
   - 上記「0-2」でビルドした `app-debug.apk` をコピーし、サーバー用フォルダ `C:\ソリューション開発\server\app.apk` として配置します（※ファイル名を `app.apk` にリネームしてください）。
3. **スマホへのアプリインストール**:
   - スマホとサーバーPCを同じWi-Fi（ローカルネットワーク：同一の無線ルーターに接続されたネットワーク範囲）に接続します。
   - スマホのカメラで、サーバー起動時のPC画面に表示されたQRコードをスキャンするか、ブラウザでダウンロードURL（例：`http://<PCのIPアドレス>:5000/download`）にアクセスします。
   - 画面の案内に従ってアプリをスマホにインストールし、起動します。
4. **アプリからの接続確認とログイン**:
   - アプリを起動すると、ネットワーク上のサーバーをmDNS（機器同士が自動的に接続相手を探し出す仕組み）で自動探索します。
   - 自動探索が成功すると、ログイン画面に進むことができます。任意のテストユーザーIDとパスワードを入力してログインします。
5. **OCR認識とテスト登録**:
   - アプリのカメラ機能を使って製品コードのOCR（文字認識）を行い、製品登録を行います。
   - 登録後、履歴画面で「手動同期」ボタンを押すか、バックグラウンドの自動同期（15分間隔）を待つことで、サーバーへデータが送信されます。
6. **サーバーダッシュボードでの確認**:
   - PCのブラウザで `http://localhost:5000/admin` を開き、スマホで登録したデータがダッシュボードの履歴一覧に正しく反映されていることを確認します。

## 0-1. 検出モジュールの位置づけ

- 本システムの検出モジュールは、**Androidアプリ内で動作するオンデバイスOCR**です。
- 検出モデル（`det.onnx`）と認識モデル（`ppocr_rec.onnx`）をアセットとして内包し、端末上で推論します。
- 主な処理は以下です。
  - 画像前処理（リサイズ、コントラスト補正）
  - 文字領域検出（DBNet）
  - 文字認識（SVTR）
  - 製品コード照合（ラベルマッチング）

## 1. （他のスマホへの）インストール方法

### 1-1. 事前準備（USB接続で行う場合）

PC側:
- Android Studio / JDK 17+ / ADB が利用可能
- リポジトリを配置済み

スマホ側:
- 開発者向けオプション of **USBデバッグ ON**
- PC接続時の「USBデバッグを許可」を承認

### 1-2. 単体端末にインストール（開発者向け・USB接続）

PowerShellでプロジェクトルートに移動し、以下を実行します。

```powershell
cd C:\ソリューション開発
.\gradlew.bat installDebug
```

### 1-3. 複数端末へ一括インストール（開発者向け・USB接続）

接続されている全端末に debug APK を配布する場合:

```powershell
cd C:\ソリューション開発
.\scripts\install_all.ps1
```

このスクリプトは以下を自動で実施します。
- APKが無ければ `assembleDebug` を実行
- `adb devices` で接続端末を列挙
- 各端末へ `adb install -r` で上書きインストール
- インストール後、アプリ起動

### 1-4. 同一Wi-Fi経由でのQRコードダウンロード・インストール（現場向け・推奨）

PCとスマートフォンをUSB接続することなく、同一ネットワーク環境内でワイヤレスにアプリを配布・インストールすることができます。

#### 手順:
1. **アプリ（APKファイル）の配置**:
   - ビルド済みの本物アプリファイル（[app-debug.apk](file:///C:/ソリューション開発/app/build/outputs/apk/debug/app-debug.apk)）を `server\app.apk` にコピーして配置しておきます。
2. **管理サーバーの起動**:
   - PC側で以下のコマンドを実行してサーバーを起動します。
     ```powershell
     python C:\ソリューション開発\server\main.py
     ```
   - 起動時のコンソール（コマンド画面）に表示される「アプリダウンロード用URL（例：`http://10.192.141.183:5000/download`）」を確認します。
3. **専用ページへアクセス**:
   - スマートフォンをサーバーPCと同一のWi-Fiネットワークに接続します。
   - スマートフォンのブラウザで上記URLにアクセスするか、表示されたダウンロード用QRコードをスマートフォンのカメラでスキャンします。
4. **インストール実行**:
   - 専用ダウンロードページの手順に従って「直接ダウンロード」ボタンをタップし、インストールを行います。（初回インストール時は「提供元不明のアプリのインストール許可」を設定画面で有効にしてください）

### 1-5. インストール確認チェックリスト

- `adb devices` で端末が `device` 状態になっている（USB接続時）
- 端末にアプリアイコンが表示される
- 起動後にログイン画面が表示される
- カメラ権限を許可できる

## 2. （再学習等で性能upするための）学習・更新ガイド

現行リポジトリでは、学習ジョブ自体は同梱されていません。  
運用としては **PaddleOCR系モデルを学習/再学習 → ONNX変換 → Androidアセット差し替え** で更新します。

## 2-1. 更新パターンの選び方

### A. 軽微な性能改善（まず推奨）
- `OcrEngine.kt` の閾値・上限値などを調整
- 例: BFS閾値、最小ピクセル数、最大検出数、拡張率
- 特徴: 実装コストが低く、現場条件に合わせやすい

### B. 中～大規模改善
- PaddleOCRで再学習した検出/認識モデルをONNX化して差し替え
- 特徴: データに合えば改善幅が大きい

## 2-2. モデル更新の標準フロー

1. 学習データを準備（現場画像・正解ラベル）
2. PaddleOCRで再学習（検出/認識）
3. ONNXへ変換
4. 必要に応じて量子化
5. Androidの `app\src\main\assets\` へ配置
6. アプリを再ビルドして実機検証
7. 問題なければ配布

## 2-3. ONNX変換（例）

```bash
pip install paddle2onnx
pip install paddleocr
```

```bash
# 検出モデル変換（例）
paddle2onnx \
  --model_dir ./inference_det \
  --model_filename inference.pdmodel \
  --params_filename inference.pdiparams \
  --save_file det_model.onnx \
  --opset_version 11

# 認識モデル変換（例）
paddle2onnx \
  --model_dir ./inference_rec \
  --model_filename inference.pdmodel \
  --params_filename inference.pdiparams \
  --save_file rec_model.onnx \
  --opset_version 11
```

（任意）量子化:

```bash
python -m onnxruntime.quantization.preprocess --input det_model.onnx --output det_model_prep.onnx
python -m onnxruntime.quantization.quantize_dynamic --model_input det_model_prep.onnx --model_output det_model_quantized.onnx
```

## 2-4. Android反映手順

1. 既存モデルをバックアップ
2. `det.onnx` / `ppocr_rec.onnx` を置換
3. `DET_SIZE` と検出モデル入力サイズの整合を確認（必須）
4. `assembleDebug` → 実機で認識精度・速度を評価

### 重要注意

- `DET_SIZE` と検出モデル入力サイズが不一致だと精度が大きく低下します。
- まずはパラメータ調整（`docs\ocr_parameters.md`）で改善余地を確認してから、再学習に進むのが安全です。

## 2-5. 更新後の最低検証項目

- 明るい屋外（鉄骨刻印）
- 暗所/逆光
- 斜め撮影
- 長い製品コード
- 連続撮影時の処理時間と端末発熱
- 誤検出率（背景ノイズ）

## 3. 想定されるエラーとその対処法

## 3-1. インストール・配布系

### エラー: `adb devices` に端末が出ない（USB接続時）
対処:
- 端末のUSBデバッグ有効化
- USBケーブル交換
- ドライバ確認（Windows）
- `adb kill-server` → `adb start-server`

### エラー: `install_all.ps1` で「接続デバイスが見つからない」
対処:
- `adb devices` の出力を先に確認
- unauthorized の場合、端末でPC認証を許可

### エラー: インストールは成功するが自動起動しない
対処:
- `install_all.ps1` 内で指定されているパッケージ名（`$PACKAGE`）が古いままになっている可能性があります。アプリID（debug suffix）と起動Activity指定の不一致を確認してください。
- 必要に応じて以下のコマンドで手動起動してください:

```powershell
adb -s <端末ID> shell monkey -p com.crossvision.f.saito19 -c android.intent.category.LAUNCHER 1
```

### エラー: アプリを開こうとすると「パッケージの解析中に問題が発生しました」と表示される（QRコードダウンロード時）
対処:
- 配信対象の `app.apk` が中身のないダミーファイルになっている可能性があります。
- プロジェクト内で正しくビルドされた本物のアプリファイル（[app-debug.apk](file:///C:/ソリューション開発/app/build/outputs/apk/debug/app-debug.apk)）を、`server\app.apk` に上書きコピーして再度ダウンロードをお試しください。

### エラー: QRコードのスキャン後、ページが開かない、または接続タイムアウトになる
対処:
- スマートフォンがサーバーPCと本当に**同じWi-Fi（ローカルネットワーク）**に接続されているか確認してください。
- サーバーPCのセキュリティソフトやWindowsファイアウォールによって、ポート5000番の通信がブロックされている可能性があります。PC側で一時的にセキュリティ許可を行ってください。

## 3-2. OCR実行系

### エラー: 「認識に失敗しました」
対処:
- 画像品質（ぼけ・傾き・暗さ）を確認
- 端末のメモリ逼迫時はアプリ再起動
- モデルファイル破損・差し替えミスを確認

### エラー: 誤検出が増える / 文字が拾えない
対処:
- `docs\ocr_parameters.md` のBFS閾値・最小ピクセル数を調整
- 刻印向けか暗所向けかで閾値を分けて評価

### エラー: 長いコードが途中で欠ける
対処:
- `MAX_REC_WIDTH` を確認
- クロップ拡張率（X/Y）を見直し

## 3-3. 同期・通信系

### エラー: サーバー同期されない
対処:
- スマホとサーバーPCが同一ネットワークか確認
- サーバー `:5000` 起動確認（`/health`）
- ファイアウォール設定確認

### エラー: mDNS検出が不安定
対処:
- 同一セグメント接続を確認
- ネットワーク機器のマルチキャスト制限を確認
- 手動でサーバーURL指定できる運用を併用

## 3-4. サーバー起動系

### エラー: `zeroconf` が無いなどのモジュール不足
対処:
プロジェクト内の設定ファイルを使って、必要なモジュールを一括インストールしてください。

```bash
pip install -r C:\ソリューション開発\server\requirements.txt
```
（※単体で不足している場合は `pip install zeroconf` などを実行します）
